# UX-рецензент сайта — автономный агент

Даёшь агенту адрес страницы — он загружает её, сам решает, что это за страница и по каким
критериям её судить, а затем возвращает UX-отчёт: сильные стороны, слабые места и пять
конкретных рекомендаций.

Итоговый проект курса «VIBE-CODING и автономные агенты» (Zerocoder), урок VCd03,
вариант №3 из банка рандомайзера — «UX-рецензент сайта».

---

## Что делает

```
адрес страницы
      ↓
загрузка HTML  →  очистка от скриптов и разметки (BeautifulSoup)
      ↓
шаг 1: агент определяет тип страницы, аудиторию, целевое действие
       и САМ формулирует 4–6 критериев разбора
      ↓
шаг 2: разбор страницы по собственным критериям
      ↓
отчёт: summary · плюсы · минусы · 5 рекомендаций (проблема → действие → приоритет)
```

Почему шагов два, а не один: тема урока — *автономный* агент, то есть программа, которая
сама решает, что делать. Разбор лендинга и разбор блога получаются разными не потому, что
для них написаны два промпта, а потому, что агент выбрал для них разные критерии. Шаг 1
отключается флагом `--no-plan`, если важнее сэкономить один запрос.

## Быстрый старт

```bash
git clone <адрес этого репозитория>
cd vcd03-ux-reviewer

python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # Linux/macOS
pip install -r requirements.txt

copy .env.example .env         # и вписать свой ключ в API_KEY
python agent.py https://example.com
```

### Ключ и провайдер

Модель вызывается через **provod.ai** — российский агрегатор с OpenAI-совместимым API:
работает без VPN и оплачивается рублёвой картой, а библиотека используется официальная
(`openai`), меняется только `base_url`. Переезд на другого совместимого провайдера — это
правка `BASE_URL` в `.env`, кода он не касается.

```ini
API_KEY=ваш_ключ
BASE_URL=https://api.provod.ai/v1
MODEL=openai/gpt-5.4-mini
```

`.env` в репозиторий не попадает (`.gitignore`), в образ не вшивается — подставляется при
запуске через `env_file`.

## Как запускать

```bash
python agent.py https://site.ru                      # отчёт в терминал
python agent.py https://site.ru --json               # машинный вывод
python agent.py https://site.ru --out report.json    # сохранить в файл
python agent.py https://site.ru --no-plan            # один запрос вместо двух
```

Коды возврата: `0` — отчёт получен, `1` — страница не загрузилась, `2` — ошибка модели,
`3` — прервано пользователем. Нужны для запуска из скриптов и cron.

### Веб-сервис

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

| Метод | Ручка | Что делает |
|---|---|---|
| GET | `/` | краткая справка о сервисе |
| GET | `/health` | проверка живости (для Docker и мониторинга) |
| GET | `/docs` | Swagger UI — здесь удобно проверять руками |
| POST | `/review` | разбор страницы: `{"url": "...", "with_plan": true}` — **нужен заголовок `X-API-Token`** |

⚠️ `POST /review` нельзя проверить, просто открыв адрес в браузере, — вернётся
`405 Method Not Allowed`. Для ручной проверки есть Swagger.

### Docker

```bash
docker compose up --build
```

Журнал вынесен наружу томом `./logs`: контейнер пересоздаётся, история разборов остаётся.

## Устройство

Система собрана слоями, слой опирается только на слой под собой:

| Слой | Файл | Знает про | НЕ знает про |
|---|---|---|---|
| точки входа | `agent.py`, `app/` | оркестрацию | промпты, HTTP-детали |
| анализ | `ux_reviewer/analyzer.py` | промпты, контракт отчёта | сеть, устройство клиента |
| модель | `ux_reviewer/llm_client.py` | API провайдера | UX и разбор страниц |
| загрузка | `ux_reviewer/fetcher.py` | HTTP и HTML | модель |
| журнал | `ux_reviewer/logging_setup.py` | — | — |

Смысл разделения практический: дефект ищется бисекцией. Пустой отчёт при живой странице —
слой анализа; ошибка соединения — загрузка или клиент. В каждой строке лога стоит имя слоя,
поэтому «где сломалось» видно до чтения кода.

### Проверки на границах

Самый дорогой отказ — не падение, а тихое искажение: шаг отработал, ошибок нет, результат
неверен. Поэтому:

- **пустая страница ≠ успех.** Если из HTML извлеклось меньше 200 знаков, агент отказывается
  работать и говорит почему. Без этой проверки модель получила бы пустой текст и честно
  сочинила бы UX-отчёт ни о чём — а выглядело бы это как рабочий результат;
- **код 200 ≠ то, что нужно.** Отдельно проверяется, что пришёл HTML, а не PDF или JSON;
- **пустой ответ модели = ошибка.** У reasoning-моделей пустой ответ означает, что весь
  бюджет токенов ушёл в скрытые рассуждения, — это отказ, а не «модель промолчала»;
- **число рекомендаций сверяется с ТЗ.** Модель может ответить формально успешно и дать три
  рекомендации вместо пяти; такой ответ выравнивается, а расхождение пишется в журнал;
- **откат на запасной путь не молчит.** Если шаг 1 не удался, разбор идёт по общим критериям,
  но в журнале появляется WARNING — иначе деградация останется незамеченной.

### Защита сервиса

Сервис принимает адрес от постороннего человека и тратит на каждый разбор платные
запросы к модели. Отсюда четыре меры — они нужны ровно с того момента, как сервис
становится доступен снаружи:

- ⭐ **SSRF.** Главная дыра такого сервиса: посетитель может заставить его сходить
  туда, куда снаружи хода нет, — на `127.0.0.1`, во внутреннюю сеть или на
  `169.254.169.254`, где облако отдаёт ключи от панели хостера. Поэтому имя хоста
  **резолвится**, и решение принимается по фактическим адресам (проверять текст
  адреса бесполезно — домен можно завести с любым A-именем). Переходы обрабатываются
  вручную: каждый шаг цепочки проверяется заново, иначе внешний сайт ответит
  «перейди на 127.0.0.1» и уведёт проверку в сторону. Схемы — только http/https,
  порты — только веб-порты.
- **Токен доступа** `X-API-Token`, сверяется через `compare_digest`. ⭐ Fail-closed:
  если `APP_TOKEN` не задан, ручка отвечает 503, а не работает открыто — забытая
  настройка не должна превращаться в публичный платный API.
- **Ограничение частоты** — 20 разборов в час с адреса (настраивается). Защищает
  бюджет даже при утёкшем токене. `X-Forwarded-For` учитывается, только если
  `TRUST_PROXY=true`, иначе его подделает кто угодно.
- **CORS закрыт по умолчанию**, вес скачиваемой страницы ограничен 5 МБ, наружу
  отдаются общие формулировки ошибок — подробности только в журнал.

### Журнал

Пишется сразу в двух местах: в консоль (для человека за терминалом) и в файл
`logs/ux-reviewer.log` с ротацией по 1 МБ × 3 (для расследования постфактум — под Docker и
cron консольный вывод теряется). В каждой строке: время, уровень, слой, числа — сколько
знаков загружено, сколько токенов потрачено, сколько пунктов в отчёте.

## Проверка качества

```bash
python -m unittest discover -s tests   # 17 тестов, без сети и без обращений к модели
python -m ruff check .                 # PEP8
python -m mypy agent.py ux_reviewer app  # типизация
```

Тесты намеренно не ходят в сеть: клиент модели подменяется заглушкой, поэтому они проходят
на машине без ключа и без интернета и ничего не стоят. Проверяются границы — то, что модель
может нарушить: не то число рекомендаций, строки вместо объектов, обрезанная страница.

## Соответствие ТЗ урока

| Требование | Где выполнено |
|---|---|
| Запуск одной функцией с аргументом `url` | `agent.run(url)` — её же зовёт веб-сервис |
| Загрузка HTML и чистый текст через BeautifulSoup | `ux_reviewer/fetcher.py` |
| Агент сам формирует план работы | `analyzer._plan_criteria()` — шаг 1 |
| Все обращения к модели в одном модуле | `ux_reviewer/llm_client.py` |
| Повторы до 3 раз с экспоненциальной задержкой | `tenacity` в клиенте и в загрузке |
| Ключ в `.env`, не в коде | `.env.example`, файл `.env` вне git |
| Логи без ключей и секретов | пишутся только числа и адреса, тело ошибки обрезается |
| PEP8 + типизация | `ruff check .` и `mypy` — чисто, настройки в `pyproject.toml` |
| Python ≥ 3.10, заданные зависимости | `requirements.txt` |
| Тесты проходят | 34 теста, `python -m unittest discover -s tests` |

⚠️ Одно расхождение с текстом ТЗ, названное явно: там модуль работы с моделью
назван `openai_module.py`, а в практической части урока тот же файл создаётся как
`llm_client.py`. Выбрано имя из практики урока; требование «все обращения к модели
централизованы в одном модуле» выполнено.

## Грабли, пойманные при сборке

Записаны, потому что каждая стоила времени и повторится у следующего, кто возьмёт этот код.

1. **`.env` грузился только в CLI.** Из командной строки агент работал, а тот же код через
   HTTP падал с «не задан API_KEY»: `load_dotenv()` стоял в `agent.py` и отсутствовал в
   `app/main.py`. Две точки входа — два места, где окружение обязано быть загружено.
2. **Библиотека `openai` 3.x перешла с `httpx` на `httpx2`.** Прямой импорт `httpx` ради
   перехвата сетевых исключений ронял модуль целиком. Ловить нужно исключения самой
   библиотеки (`APIConnectionError`), а не её внутреннего HTTP-клиента.
3. **Часть моделей у provod не принимает `temperature`** и отвечает ошибкой без имени
   виноватого параметра. Лечится таблицей `MODEL_QUIRKS` в `ux_reviewer/llm_client.py`:
   для ветки `openai/gpt-5.4*` параметр выбрасывается, а reasoning отключается явно.
   Добавляете новую модель — сначала проверьте её голым запросом.
4. **Консоль Windows не в UTF-8**: русский текст в логе превращался в «????», при этом в
   файл писалось верно — дефект выглядит загадочно, лечится `sys.stdout.reconfigure`.
5. **`get_text()` без разделителя склеивает слова** соседних блоков в «Каталогдоставкаоплата»,
   и модель читает мусор.
6. **`secrets.compare_digest` со строками работает только для ASCII** — на токене с
   кириллицей бросает `TypeError`, то есть ручка отвечала бы 500 вместо честного отказа.
   Токен приходит снаружи, прислать можно что угодно. Лечится `.encode("utf-8")`;
   поймано тестом, а не в проде.
7. **Диапазоны из документации (`198.51.100.0/24`, `203.0.113.0/24`) Python считает
   приватными** — тест «публичный адрес проходит» на них падал, хотя проверка была верной.
   Для положительных случаев нужен по-настоящему публичный адрес.

## Ограничения

- Агент видит **только текст** страницы: картинки, цвета, вёрстку и поведение при прокрутке
  он не оценивает и в промпте прямо предупреждён не делать вид, что видит их.
- Страницы, которые собираются скриптами в браузере (SPA), отдают почти пустой HTML — агент
  честно откажется их разбирать. Обход — рендеринг через headless-браузер, в этот проект
  не входит.
- Длинные страницы разбираются по первым 40 000 знаков, о чём отчёт сообщает отдельной
  строкой.
